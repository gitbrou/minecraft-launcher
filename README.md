# Mine Launcher

Лаунчер Minecraft, который я делаю для себя и друзей. Electron, React, TypeScript.

Запускает ваниллу, Fabric и Quilt, ставит моды с Modrinth, сам скачивает подходящую Java.
Обновляется через GitHub Releases: пришло обновление — лаунчер скачал его в фоне и поставил
при выходе. Новая версия не требует «скачай установщик заново».

![Скриншот лаунчера](docs/screenshot.png)

## Что умеет

Сборки лежат отдельными папками. У каждой своя версия игры, свой список модов и свои миры,
а библиотеки, ассеты и скачанные версии — общие. Поэтому вторая сборка на той же версии
почти ничего не весит.

Моды можно искать прямо в лаунчере: он показывает только то, что подходит к версии игры и
загрузчику выбранной сборки. Включение и выключение — без переименования `.jar` руками,
имя файла при этом остаётся настоящим (с плюсами и пробелами, как у Fabric API).

Java ставить заранее не нужно. Лаунчер смотрит, какая версия нужна игре, ищет её на диске,
а если не нашёл — качает Temurin JRE 8, 17 или 21. В настройках можно указать свой путь.

Про аккаунты: только оффлайн-ники, UUID считается по стандарту OfflinePlayer. Скин можно
загрузить PNG-файлом или скачать по нику, посмотреть — в 3D.

Ещё умеет экспортировать сборку в zip и импортировать обратно, в том числе по ссылке
`minelauncher://import?url=…`. Логи игры идут в реальном времени; если игра упала, лаунчер
пробует объяснить причину (мало памяти, не та Java, нет VC++, CDN Mojang, драйвер).

## Чего нет

- Forge. Пока только Vanilla, Fabric и Quilt.
- Входа через Microsoft. Оффлайн-ники, без скинов с официальных аккаунтов и без серверов,
  которые требуют лицензию.
- Автообновлений на Linux и macOS. На Linux проверка обновлений отключена, на macOS
  `electron-updater` требует подписанное приложение, а сборка не подписана.
- Готового Android-клиента. В репозитории лежит Capacitor-заглушка с мостом на
  PojavLauncher, но это не релизная сборка.

## Сборка

Нужен Node.js 18+ и npm. Java для сборки не нужна, её лаунчер скачает сам.

```bash
cd mine-launcher
npm install

npm run dev       # разработка, Vite + Electron
npm test          # тесты, сеть не нужна
npm run lint
npm run build     # установщик и portable в dist-build/
```

`npm run build` собирает NSIS-установщик и portable-версию для Windows x64. Linux и macOS
собираются на своих системах: цели AppImage и dmg описаны в `package.json`.

Сейчас 65 тестов. Они про то, что легко сломать незаметно: правила библиотек Mojang и
безопасность путей, формат offline-UUID, выбор Java под версию игры, разбор падений,
распаковка zip (zip-slip, symlink, лимиты) и парсер `minelauncher://` ссылок.

## Где лежат данные

Внутри `app.getPath('userData')/.mine-launcher`:

- Windows: `%APPDATA%\mine-launcher\.mine-launcher`
- Linux: `~/.config/mine-launcher/.mine-launcher`
- macOS: `~/Library/Application Support/mine-launcher/.mine-launcher`

Там `accounts.json`, `instances.json`, `settings.json`, а рядом папки `instances/`, `assets/`,
`libraries/`, `versions/`, `java/`, `skins/`. Если что-то совсем сломалось, для начала можно
переименовать `settings.json` — лаунчер создаст новый с настройками по умолчанию.

## Обмен сборками

Экспорт — через меню «…» у сборки: получается zip с `instance.json` и содержимым `mods/`.
Импорт — кнопка «Импорт» или ссылка:

```
minelauncher://import?url=https%3A%2F%2Fexample.com%2Fsurvival.zip
```

Перед скачиванием лаунчер показывает хост и спрашивает подтверждение. Разрешён только
`https`, не больше трёх редиректов, архив не больше 600 МБ. Пути наружу, symlink-записи и
превышение размера после распаковки отсекаются до записи на диск.

## Обновления

Работают у установленной Windows-сборки (NSIS). В `npm run dev` проверка выключена.

1. Поднять версию в `mine-launcher/package.json`.
2. Поставить тег `vX.Y.Z` (такой же, как версия) и запушить — GitHub Actions соберёт релиз.
3. В релиз должны попасть `.exe`, `.blockmap` и `latest.yml`. Без `latest.yml` лаунчер
   обновление не увидит, это самое частое место, где всё молча ломается.

Клиент проверяет обновления при старте и раз в четыре часа. Скачивает в фоне, ставит при
выходе или по кнопке в баннере. Если что-то пошло не так, ошибка видна в том же баннере.

## Безопасность

- `contextIsolation` включён, `nodeIntegration` выключен, переходы окна наружу запрещены.
- IPC проверяет id сборок, имена файлов и пути; моды качаются только с `cdn.modrinth.com`.
- Zip распаковывается своим кодом, а не `extract-zip` (у него долго висел symlink traversal):
  проверяются абсолютные пути, `..`, symlink-записи и реальный размер распаковки.
- `npm audit --omit=dev` — без уязвимостей в production-зависимостях.

## Если что-то не работает

Заведите issue и приложите лог из вкладки «Логи» — по нему обычно сразу видно, чего не
хватило. Полезно указать версию Windows, сборку и что ставили перед этим.

Windows-сборка не подписана, поэтому SmartScreen будет ругаться на установщик. Это ожидаемо,
пока нет сертификата. macOS-сборка тоже не нотаризована. Electron 30.x уже не самый свежий,
в нём есть известные CVE; переезд на новую ветку — отдельная задача, там ломается API.
