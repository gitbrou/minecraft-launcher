# Mine Launcher

Лаунчер Minecraft, который я делаю для себя и друзей. Electron, React, TypeScript.

Началось с того, что надоело каждый раз запускать игру вручную и раскладывать моды по
папкам. Сейчас лаунчер сам качает нужную Java, ставит моды с Modrinth и обновляется
через GitHub Releases. Делаю по вечерам, так что местами может быть грубовато.

![Скриншот](docs/screenshot.png)

## Что умеет

Ванилла, Fabric и Quilt. У каждой сборки своя папка: свой набор модов, свои миры, своя
версия игры. Библиотеки, ассеты и версии игры общие, поэтому вторая сборка на той же
версии почти ничего не весит.

Моды ищутся прямо в лаунчере, фильтр по версии игры и загрузчику уже стоит. Включать и
выключать можно без переименований `.jar`; имена вроде `fabric-api-0.165.0+26.3.jar`
не ломаются.

Java (Temurin 8, 17 или 21) скачивается сама, если нужной нет на диске. В настройках
можно указать свой путь, если хочется.

Про аккаунты: только оффлайн-ники, UUID считается как в OfflinePlayer. Скин можно
загрузить PNG или скачать по нику, посмотреть в 3D.

Сборку можно выгрузить в zip и импортировать обратно, в том числе по ссылке
`minelauncher://import?url=…`.

Логи игры идут вживую. Когда игра падает, лаунчер пытается объяснить причину: мало
памяти, не та Java, нет VC++, недоступен CDN Mojang. Иногда получается.

## Чего нет

Forge и входа через Microsoft. Только оффлайн, так что на серверы с лицензией не пустит.
Android я выпилил: интеграции не было, была только заготовка.

Автообновления работают на Windows. На Linux проверка отключена, на macOS для
electron-updater нужна подпись приложения, а её нет.

## Сборка

Нужен Node 18+ и npm. Java не нужна.

```bash
cd mine-launcher
npm install
npm run dev
```

`npm test` — 65 тестов, сеть не требуется. `npm run lint` — eslint. `npm run build`
собирает NSIS-установщик и portable в `dist-build/`.

AppImage и dmg тоже прописаны в `package.json`, но собирать их лучше на своей системе.
Больше всего тестировал на Windows 10/11.

## Где данные

`%APPDATA%\mine-launcher\.mine-launcher` на Windows. На Linux
`~/.config/mine-launcher/.mine-launcher`, на macOS
`~/Library/Application Support/mine-launcher/.mine-launcher`.

Внутри `accounts.json`, `instances.json`, `settings.json` и папки `instances/`, `assets/`,
`libraries/`, `versions/`, `java/`, `skins/`. Если что-то сломалось, для начала можно
удалить `settings.json`: лаунчер создаст новый.

## Импорт по ссылке

```
minelauncher://import?url=https%3A%2F%2Fexample.com%2Fsurvival.zip
```

Лаунчер показывает хост и спрашивает подтверждение. Только https, не больше трёх
редиректов, архив до 600 МБ. Пути наружу и symlink-записи отбрасываются до распаковки.

## Релизы и обновления

Версия лежит в `mine-launcher/package.json`. Чтобы выпустить обновление, ставлю тег
`vX.Y.Z` (совпадает с версией) и пушу. GitHub Actions собирает exe, dmg и AppImage,
прикладывает к релизу и обновляет `latest.yml`.

Для Windows `latest.yml` обязателен: без него лаунчер не увидит новую версию. Один раз я
уже на этом попался. Проверяет обновления при старте и раз в четыре часа, качает в фоне,
ставит при выходе.

## Безопасность

`contextIsolation` включён, `nodeIntegration` выключен. IPC проверяет id сборок и имена
файлов, моды качаются только с `cdn.modrinth.com`. Zip распаковываю сам: проверяю
абсолютные пути, `..`, symlink-и и фактический размер после распаковки.

## Если что-то пошло не так

Установщик не подписан, SmartScreen будет ругаться. macOS-сборка не нотаризована.
Electron 30.x уже старый, в нём есть известные CVE; переезд на новую ветку — отдельная
задача.

По багам лучше открыть issue и приложить лог из вкладки «Логи»: обычно по нему видно,
чего не хватило.
